О программе.txt — Блокнот

DedupCommando — консольный командир дедупликации для ZFS-пулов на Proxmox VE. Находит идентичные файлы, собирает их в группы и возвращает терабайты — со снапшотом-страховкой перед каждым действием. · один бинарь, без демона, по SSH · хеш blake3, перепроверка перед каждым изменением · обкатка на боевом хосте Proxmox VE Двойной щелчок по значкам открывает разделы.

Возможности

Двухпанельный TUI

Группы слева, файлы справа, всё с клавиатуры. SSH, tmux, хоть консоль IPMI. Для первого раза — мастер --classic.

Снапшот перед действием

ZFS-снапшот создаётся автоматически до удаления, hardlink или reflink. Откат возвращает к этому моменту весь датасет.

Сверка, а не вера

Группы по blake3, и прямо перед изменением каждый файл проверяется заново: изменившийся файл не трогается. Сверка байт в байт — ключ --verify.

Атомарно или никак

renameat2(RENAME_NOREPLACE) вместо «проверил — потом переименовал»: существующий файл никогда не перезаписывается молча.

Профиль Idle

Скан идёт с самым низким приоритетом процессора и дисков (nice 19, ionice idle): виртуалки и бэкапы — первыми.

Чекпойнты

Состояние в dedcom.db: прервали скан — продолжится с того же места.

Один бинарь на Rust

Файл dedcom — и всё: без демона и веб-морды. Нужна glibc ≥ 2.39 (Debian 13, Proxmox VE 9).

Headless для скриптов

--scan, --stats, --export-csv — для cron и отчётов.

Свойства: Безопасность

Протокол безопасности встроен и не отключается — поэтому флажки серые:

✓Снапшот-страховка

ZFS-снапшот автоматически перед каждым действием. Секунды на боевом пуле — и спасённые терабайты.

✓Повторная сверка

Прямо перед действием — ре-хеш. Расхождение — стоп, группа на пересмотр.

✓Атомарные операции

renameat2(RENAME_NOREPLACE): состояние гонки исключено самим системным вызовом.

✓Карантин вместо пропасти

«Удаление» переносит файлы в карантин. Вернуть можно точечно, без отката снапшота.

⚠ На ZFS деструктивная партия не запускается без снапшота: если снапшот не создался, партия отменяется. Это инвариант в коде, а не настройка. Без ZFS снапшота нет, поэтому применять действия там не рекомендуется.

Листинг 1 — установка из APT-репозитория (Debian 13, Proxmox VE 9+) 
# от root (так по умолчанию в Proxmox); в Debian без root: sudo -i
curl -fsSL https://dedupcommando.github.io/apt/dedcom-archive-keyring.gpg \
  -o /usr/share/keyrings/dedcom-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/dedcom-archive-keyring.gpg] https://dedupcommando.github.io/apt stable main" \
  | tee /etc/apt/sources.list.d/dedcom.list
apt update && apt install dedcom
dedcom --classic            # пошаговый мастер для первого раза
Листинг 2 — сначала репетиция 
# одноразовый loopback-пул с дубликатами: полигон без риска
./scripts/make-test-pool.sh
dedcom                      # потренируйтесь, потом на боевой

Справка: вопросы и ответы

Насколько это безопасно на боевом хосте?

Перед любым деструктивным действием — автоматический ZFS-снапшот, повторная проверка каждого файла и атомарные операции. «Удалённое» уходит в карантин. Худший сценарий — откат датасета к снапшоту, при котором пропадёт и всё записанное после него. Профиль Idle сканирует с самым низким приоритетом процессора и дисков.

Hardlink? А что с клонированием блоков?

Классический режим — hardlink. Где OpenZFS умеет block cloning, доступен reflink — файлы независимы, но делят блоки. Результат проверяется по фактическому размещению данных, а не по косвенным счётчикам.

Почему TUI, а не веб-интерфейс?

Лишний демон и порт на хранилище — минус к безопасности. SSH уже есть; dedcom рисует интерфейс в любом терминале. Для скриптов — headless: --scan, --stats, --export-csv.

Скан на терабайтах прервался — всё заново?

Нет: состояние в чекпойнтах (dedcom.db), после перезапуска скан продолжится с места остановки.

Что нужно для запуска?

Linux x86-64 или arm64 с glibc 2.39 и новее (Debian 13, Ubuntu 24.04, Proxmox VE 9), пул OpenZFS и терминал. Один бинарь, без демона. Proxmox VE — родная среда, но подойдёт любой хост с ZFS.

Загрузка dedcom

В Debian 13 и Proxmox VE 9 ставится через apt (см. окно «Установка»). На других Linux с glibc 2.39 и новее скачайте релиз на GitHub, проверьте его и скопируйте бинарь на хост.
