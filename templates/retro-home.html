DedupCommando — a terminal dedup commander for ZFS pools on Proxmox VE. It finds identical files, gathers them into groups and reclaims the space — with a safety snapshot before every action. · one binary, no daemon, over SSH · blake3 hashing, re-checked before every change · tested on Proxmox VE 9.1 (OpenZFS 2.3) Double-click the icons to open the sections.

Features

Dual-pane TUI

Groups on the left, files on the right, all from the keyboard. SSH, tmux, the Proxmox web shell. First run? The --classic wizard.

Snapshot before action

A ZFS snapshot is taken automatically before any delete, hardlink or reflink. A rollback returns the whole dataset to that moment.

Verify, don’t trust

Groups by blake3, and every file is checked again right before a change: a file that changed is left alone. Byte-for-byte compare: --verify.

Atomic or nothing

renameat2(RENAME_NOREPLACE) instead of “check, then rename”: an existing file is never silently overwritten.

Idle profile

Scans at the lowest CPU and disk priority (nice 19, ionice idle) and asks the disk to let VMs and backups go first.

Checkpoints

State lives in dedcom.db: interrupt a scan and it resumes where it stopped.

One Rust binary

The dedcom file is all there is: no daemon, no web UI. Needs glibc 2.39+ (Debian 13, Proxmox VE 9).

Headless for scripts

--scan, --stats, --export-csv — for cron and reports.

Properties: Safety

The safety protocol is built in and cannot be switched off — that’s why the boxes are greyed out:

✓Safety snapshot

A ZFS snapshot automatically before every action. It keeps the old data until you destroy it.

✓Re-verification

A re-hash right before acting. Any mismatch stops it; the group goes back for review.

✓Atomic operations

renameat2(RENAME_NOREPLACE): no window between checking the target name and the rename.

✓Quarantine, not the void

“Deleting” moves files to quarantine. Bring one back precisely, without a full rollback.

⚠ On ZFS a destructive batch cannot run without its snapshot: if the snapshot fails, the batch is aborted. An invariant in the code, not a setting. Without ZFS there is no snapshot, so delete, hardlink and reflink are refused there.

# as root (the Proxmox default); on Debian without root run: sudo -i
curl -fsSL https://dedupcommando.github.io/apt/dedcom-archive-keyring.gpg \
  -o /usr/share/keyrings/dedcom-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/dedcom-archive-keyring.gpg] https://dedupcommando.github.io/apt stable main" \
  | tee /etc/apt/sources.list.d/dedcom.list
apt update && apt install dedcom
dedcom --classic            # step-by-step wizard for the first run

Help: questions and answers

How safe is this on a production host?

Before any destructive action — an automatic ZFS snapshot, a fresh check of every file and atomic operations. “Deleted” files go to quarantine. The worst case is rolling a dataset back to its snapshot, which also drops anything written after it. The Idle profile scans at the lowest CPU and disk priority.

Hardlink? What about block cloning?

The classic mode is hardlink. Where OpenZFS supports block cloning, reflink is available — files stay independent but share blocks. The project’s E2E test proves the sharing by block address (zdb), not by pool counters.

Why a TUI and not a web UI?

An extra daemon and an open port on storage cost security. You already have SSH, and dedcom draws its interface in any UTF-8, 256-color terminal. For scripting there are headless modes: --scan, --stats, --export-csv.

A terabyte-scale scan got interrupted — start over?

No: state is checkpointed to dedcom.db, so after a restart the scan resumes where it stopped.

What do I need to run it?

Linux x86-64 or arm64 with glibc 2.39 or newer (Debian 13, Ubuntu 24.04, Proxmox VE 9), an OpenZFS pool and a terminal. One binary, no daemon. Proxmox VE is the native habitat, but any ZFS host works.

Download dedcom

On Debian 13 and Proxmox VE 9 install it with apt (see the “Install” window). On other Linux systems with glibc 2.39 or newer, download a release from GitHub, verify it and copy the binary to the host.
